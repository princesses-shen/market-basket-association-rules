## 启动与私有配置

沿用原项目的 Java 11、Maven、HBase 2.5.9 和现有业务数据。后端位于 `day08-backend`。配置参考 `config/account-security.env.example`；将值注入进程环境，Spring Boot 不会自动读取该示例文件。

必须提供 `JWT_SECRET`，至少 32 字节的随机字符串；各后端实例和重启之间保持一致。下面的 PowerShell 命令可以生成一个值，将生成值保存在部署环境的私有配置中：

```powershell
$jwtBytes = New-Object byte[] 48
$jwtRandom = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$jwtRandom.GetBytes($jwtBytes)
$jwtRandom.Dispose()
$env:JWT_SECRET = [Convert]::ToBase64String($jwtBytes)
$env:ZK_QUORUM = '127.0.0.1' # 改为现有 HBase 的 ZooKeeper 地址
mvn -f day08-backend/pom.xml package
java -jar day08-backend/target/demo-0.0.1-SNAPSHOT.jar
```

如果部署环境按原项目说明使用 `HADOOP_CLASSPATH`，继续沿用原启动方式，并向该 Java 进程传入以上环境变量。更换 JWT 密钥会使已登录凭证全部失效。

SMTP 需要配置 `SMTP_HOST`、`SMTP_PORT`、`SMTP_USERNAME`、`SMTP_PASSWORD`（邮箱授权码）、`SMTP_FROM`。默认使用 QQ 邮箱 465 SSL，设置 `SMTP_SSL=true`、`SMTP_STARTTLS=false`；使用 587 时显式设置 `SMTP_SSL=false`、`SMTP_STARTTLS=true`。发件邮箱由部署配置决定，与管理员邮箱无必然关系。

不配置邮件也能演示登录、封禁和解封；找回密码发送验证码会显示服务不可用。系统使用真实 Spring Mail SMTP 发送，不会向接口响应或日志输出明文验证码。

## 演示步骤

1. 注册一个用户和一个企业账号，均填写有效邮箱。已有 SHA-256 测试账号仍可登录；本次不补绑旧账号邮箱。
2. 用户登录成功后退出，连续输入错误密码五次。前四次显示剩余次数，第五次封禁；之后正确密码也不能登录。企业账号遵循同样规则，同名用户和企业独立计数。
3. 管理员登录后按账号类型、账号名关键词、封禁状态筛选。点击“解封”，失败次数清零；目标账号重新登录后才能使用。
4. SMTP 配置完成后，在用户或企业“忘记密码”页面输入账号和注册邮箱，收取验证码后重置密码。旧密码和旧 JWT 失效。
5. 封禁账号可重置密码，但仍需管理员解封。管理员自身不启用五次错误封禁。

## 数据与权限实现

- 不删除或重建既有业务表。启动时幂等创建缺失的 `recruit_admin`、`recruit_upload` 以及用户/企业账号表，列族均为 `info`。
- 新注册、登录、封禁、解封和重置使用 HBase 行级条件写入。安全字段在现有账号行按需写入，旧账号缺失的失败次数、凭证版本视为 0，缺失封禁状态视为正常。
- `security_revision` 是每次安全写入更新的 CAS 标记；`credential_version` 只在封禁、解封和重置时递增。每个受保护请求读取真实账号状态和版本。
- 注册通过密码列不存在的条件写入，防止并发注册覆盖密码。新用户、新企业和重置后的密码均使用 BCrypt；保留旧 SHA-256 校验，不批量改写旧账号。
- 解封审计以 `unlock_audit_<UUID>` 列保存在目标账号行，值为 `操作者|毫秒时间戳`。目标类型由表区分，目标账号由行键标识。审计与解封同一个原子 Put 持久化，保留每次记录；管理接口只返回查询白名单字段。
- 验证码使用安全随机六位数字，保存带服务器密钥的摘要。10 分钟有效；同账号间隔至少 60 秒，滚动一小时最多五次发送；单码五次验证失败后失效。重新发送撤销旧码，成功重置时在同一原子 Put 中消费验证码、更新密码与凭证版本。
- 邮件发送前原子预留发送次数并使旧码失效，SMTP 成功后才启用新码；发送失败不启用验证码，预留次数仍计入发送限额。部署重启也不会重置发送限额。
- 企业、简历、聊天、投递、人才库和附件接口接入鉴权，操作主体取自 JWT；会话、人才、附件校验归属。企业仅查看本企业人才库或本企业会话关联的完整简历。旧附件通过已有投递关系校验访问权限。
- 前端沿用原有样式，通过 `common.js` 为同源 API 和附件请求携带凭证；401 清理登录态并跳转登录页。管理员权限由后端验证，修改浏览器角色或请求中的用户名不能提升权限。
- 岗位查询、关联规则、分析算法、预测和大屏逻辑未修改。
